# GRPO v4.1 恢复实验计划

## 1. 问题与证据

v4.0 的 GRPO 从已退化的 DPO adapter 启动。DPO 采样产生不可解析的数值占位符，严格 JSON reward 将所有候选都记为 0；每组 reward 方差为 0 后，group-relative advantage 也全部为 0。最终 1,200 个微组全部饱和，所谓 GRPO loss 实际只剩 KL 项，1,416 条留出集输出全部无法解析。

本轮不更改“音频 → Whisper 表征 → projector → Qwen 处方 → 确定性 DSP”的产品逻辑，只修复 GRPO 的训练起点、奖励密度、格式保持、失效保护和验收门禁。

## 2. 可证伪假设

如果 GRPO 从已验证 JSON 有效率为 100% 的 SFT adapter 启动，并同时加入：

1. 对 JSON 前缀进度的低权重稠密奖励；
2. chosen response 的 SFT anchor loss；
3. reward 饱和监测与 fail-fast；
4. 正式训练前的生成 canary；

那么 canary 应出现可解析输出和非零组内 reward 方差，正式 GRPO 不再退化为 KL-only 训练，最终留出集 JSON 有效率应保持在发布门槛以上。

反证条件：canary 的 JSON 有效率低于配置门槛、非饱和组比例低于门槛，或连续饱和组超过上限；任一发生都必须中止，不能将该轮标记为成功。

## 3. 变量与对照

- 固定：Qwen2.5-1.5B-Instruct、Whisper-small、数据划分、audio projector、QLoRA、随机种子 42。
- 训练起点：v4.0 SFT final（主实验）；v4.0 DPO final 仅保留为失败对照，不作为正式起点。
- GRPO 主配置：6 generations、temperature 0.7、top-p 0.9、低学习率、SFT anchor。
- 奖励：五项原有可验证 reward；仅对“像 JSON 但尚未闭合”的输出增加上限很低的结构进度分。纯文本垃圾和问号占位符仍为 0。
- 验收：canary 先行；正式训练后再进行全量测试集生成、reward 报告与泛化评测。

## 4. 工程修改

1. 配置层允许 `grpo.input_stage` 为 `sft` 或 `dpo`，执行层必须真正按该字段解析 lineage。
2. 新增独立 recovery 入口，复用 v4.0 SFT final 与已有 Whisper embedding cache，不重跑 SFT/DPO。
3. 新增 reward group 诊断：均值、标准差、跨度、JSON 有效率、是否饱和。
4. 新增 canary gate：正式 optimizer step 前采样若干组并写出审计报告。
5. GRPO loss 加入 chosen-response SFT anchor；饱和组不允许静默执行纯 KL 更新。
6. 连续饱和或总尝试次数异常时写 failure report 并抛出可读错误。
7. stage manifest 记录有效 JSON、非饱和率、跳过/饱和组、各 reward 分量和 anchor loss。

## 5. 测试计划

- 单元测试：JSON 进度 reward 上限、占位符拒绝、group 诊断、anchor 梯度、canary gate、配置 lineage。
- 回归测试：完整 `pytest`、Ruff。
- 本地 CPU 合成演练：无需模型权重，验证 recovery 配置解析、产物路径和 fail-fast 逻辑。
- AutoDL GPU canary：加载真实 SFT adapter，执行至少 8 组 × 6 generations；通过门禁才进入短训练。
- 正式训练：短训练先检查 checkpoint 与指标趋势，再跑目标步数；最终以独立测试集和泛化评测判定是否晋升 GRPO。

## 6. 通过标准

- canary：`valid_json_rate >= 0.80`，`non_saturated_group_rate >= 0.20`，且无问号占位符。
- 训练：不存在连续 16 个饱和组；stage manifest 明确包含 GRPO policy signal 与 anchor 指标。
- 最终：测试集 JSON 有效率 `>= 0.99`；GRPO reward 不低于 SFT 基线；DSP 安全验证与泛化指标不得出现超出预设容差的退化。
- 若 GRPO 未通过，保留全部负结果但不发布、不替换 SFT。

## 7. 资源与时间估计

- 本地阶段：代码、测试、配置、脚本、文档，不需要 GPU。
- AutoDL：先进行约 10–30 分钟真实 canary；通过后再决定完整 GRPO 时长。复用 embedding cache 和 SFT 权重，避免重新执行约 2,300 步 SFT/DPO。
- 磁盘：新增 adapter/checkpoint/日志预计数 GB；不复制基础模型和公开数据缓存。
